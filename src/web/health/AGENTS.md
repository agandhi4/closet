# Health

The fleet's health contract (`~/.claude/conventions/observability.md`, Health Contract; `docs/decisions.md` 2026-10-13, /health/live and /health/ready). Operator view, each check and its fix: `docs/operations.md#health`.

- **Three routes, one module** (`routes.ts`), all public static paths (`src/static-prefixes.ts`: no session, no access line), `Cache-Control: no-store`:
  - `GET /health/live`: checks nothing, 200 `{status: "up"}` while the process serves. `public/js/connectivity.js`'s heartbeat HEADs it, so a down database never shows as "offline". Never rate-limited, never given a check.
  - `GET /health/ready`: 200 `{status: "up", version, checks}` or 503 `status: "down"`, down exactly when a `required: true` check is down (`readiness`, `checks.ts`). `version` is `config.release` (the bare sha7). Read by the image's `HEALTHCHECK`, `scripts/smoke-image.sh` (boot poll, `BOOT_EXPECT_VERSION`, devkit's `contract_probe.sh --health`) and Playwright's webServer wait.
  - `GET /healthz`: the same handler and the same rate-limit budget as `/health/ready`, kept for phones whose cached `connectivity.js` still HEADs it. Fastify answers HEAD from the GET route without the body (closet #379: an unread GET body held every heartbeat open 5 s).
- **Checks.** `storage` (required): `createStorageCheck` over `WebConfig.storageDirs` (DATA_PATH, MODELS_PATH), each a real write of `PROBE_BYTES` (4 KB, so a full disk or quota reads ENOSPC/EDQUOT) then unlink as the process's uid (`src/storage-probe.ts`, shared with `main.ts`'s boot refusal of an unwritable DATA_PATH), each probe raced against a 3 s bound (down with code `TIMEOUT`: a stalled share, #688), cached `STORAGE_PROBE_TTL_MS` (5 s) and single-flight so no request rate turns into disk writes (the bound is under the TTL, so the cached verdict always settles; a timed-out probe cannot be cancelled, so at most ONE is in flight per directory: while it hangs later windows answer `TIMEOUT` at once and start nothing, since each stuck fs call holds one of libuv's four pool threads, and a new probe starts only when it settles); each probe's file is `.write-probe-<pid>-<n>`, so overlapping probes never share one, and a probe removes this process's files no in-flight probe owns, so a hung write's leftover is not leaked; a problem is logged once when it appears or changes (and once healthy again), never per probe, and only the code, never the path value, reaches the body or log; its `fix` is per failure code (`storageFix`, one table in `src/storage-probe.ts`: EACCES/EPERM the chown with the process's own uid:gid, `docs/operations.md#permissions`; ENOSPC/EDQUOT the share is full; TIMEOUT the share is not answering; any other a generic pointer), one phrase per kind. It is down too when DATA_PATH lost the marker the boot claimed or holds another install's (`identity`: `PhotoStorage.identityProblem`, the marker against the id claimed and paired at boot, in memory: no statement, #650, #833; Images), with `see docs/operations.md#photo-storage-marker` as its fix. Required because the image runs non-root on host mounts: a root-owned one would otherwise read `up` until the first upload or model download failed. The probe creates a missing directory, as the writers do, so the integration harness points MODELS_PATH at the system temp dir. `database` and `migrations` (required) come from ONE statement, `lastMigrationAt(db)` (`src/db/migrate.ts`) under a 3 s bound: answering is the round-trip, its value at or past this build's newest migration (`newestMigrationAt()`, read once at registration) is the schema. `cron_jobs` (optional): `JobRoster.stuck()` (`src/maintenance/scheduled.ts`), the timers whose run has been in flight past `STUCK_AFTER_MS` (30 min); a timer schedules its next run only once a run ends, so a hung run is the one way a job silently stops. `cutout_queue` (optional): `CutoutQueue.state` (`src/cutout/queue-state.ts`): up while running, down when stopped, and down while it waits for a model it cannot have with `reason` (a closed kind: download, checksum, permission, binding, other) and that kind's `fix` (#689). Optional because every page serves without them and a restart loop would cost the household the app (as locus and Orbit). The integration harness builds the app without `serve()`, so there both optional checks are down and the app is up.
- **The body is unauthenticated**: a check carries `status`, `required`, a `fix` pointer and, for `cron_jobs`, the `stuck` names, for `cutout_queue` a `reason` kind; never an exception's text or the list of jobs that are fine. The detail goes to the log (logger `Health`, `Readiness: ...`, storage's on a transition, the others per call).
- **Rate limit**: `HEALTH_LIMIT` (`src/web/security/rate-limit.ts`), 60 a minute per client address on one `createRateLimit` checker shared by `/health/ready` and `/healthz`; past it a 429 (JSON: a static path has no page context). Per address works because closet listens directly (no in-container proxy) and `TRUSTED_PROXIES` covers Caddy.
- **A new dependency the app cannot serve without** is one more required check in `checks.ts`, fed from `routes.ts`; a background one is `required: false`. Prove a 503 path in `checks.spec.ts` (stubbed inputs) and the real round-trip in `test/integration/delivery.spec.ts`.
