# Health

The fleet's health contract (`~/.claude/conventions/observability.md`, Health Contract; `docs/decisions.md` 2026-10-13, /health/live and /health/ready). Operator view, each check and its fix: `docs/deployment.md#health`.

- **Three routes, one module** (`routes.ts`), all public static paths (`src/static-prefixes.ts`: no session, no access line), `Cache-Control: no-store`:
  - `GET /health/live`: checks nothing, 200 `{status: "up"}` while the process serves. `public/js/connectivity.js`'s heartbeat HEADs it, so a down database never shows as "offline". Never rate-limited, never given a check.
  - `GET /health/ready`: 200 `{status: "up", version, checks}` or 503 `status: "down"`, down exactly when a `required: true` check is down (`readiness`, `checks.ts`). `version` is `config.release` (the bare sha7). Read by the image's `HEALTHCHECK`, `scripts/smoke-image.sh` (boot poll, `BOOT_EXPECT_VERSION`, devkit's `contract_probe.sh --health`) and Playwright's webServer wait.
  - `GET /healthz`: the same handler and the same rate-limit budget as `/health/ready`, kept for phones whose cached `connectivity.js` still HEADs it. Fastify answers HEAD from the GET route without the body (closet #379: an unread GET body held every heartbeat open 5 s).
- **Checks.** `storage` (required): `createStorageCheck` over `WebConfig.storageDirs` (DATA_PATH, MODELS_PATH), each a real create + unlink as the process's uid (`src/storage-probe.ts`, shared with `main.ts`'s boot refusal of an unwritable DATA_PATH), cached `STORAGE_PROBE_TTL_MS` (5 s) and single-flight so no request rate turns into disk writes; its `fix` is the chown with the process's own uid:gid (`docs/deployment.md#permissions`). Required because the image runs non-root on host mounts: a root-owned one would otherwise read `up` until the first upload or model download failed. The probe creates a missing directory, as the writers do, so the integration harness points MODELS_PATH at the system temp dir. `database` and `migrations` (required) come from ONE statement, `lastMigrationAt(db)` (`src/db/migrate.ts`) under a 3 s bound: answering is the round-trip, its value at or past this build's newest migration (`newestMigrationAt()`, read once at registration) is the schema. `cron_jobs` (optional): `JobRoster.stuck()` (`src/maintenance/scheduled.ts`), the timers whose run has been in flight past `STUCK_AFTER_MS` (30 min); a timer schedules its next run only once a run ends, so a hung run is the one way a job silently stops. `cutout_queue` (optional): `CutoutQueue.running`. Optional because every page serves without them and a restart loop would cost the household the app (as locus and Orbit). The integration harness builds the app without `serve()`, so there both optional checks are down and the app is up.
- **The body is unauthenticated**: a check carries `status`, `required`, a `fix` pointer and, for `cron_jobs`, the `stuck` names; never an exception's text or the list of jobs that are fine. The detail goes to the log (logger `Health`, `Readiness: ...`, one line per failed check per call).
- **Rate limit**: `HEALTH_LIMIT` (`src/web/security/rate-limit.ts`), 60 a minute per client address on one `createRateLimit` checker shared by `/health/ready` and `/healthz`; past it a 429 (JSON: a static path has no page context). Per address works because closet listens directly (no in-container proxy) and `TRUSTED_PROXIES` covers Caddy.
- **A new dependency the app cannot serve without** is one more required check in `checks.ts`, fed from `routes.ts`; a background one is `required: false`. Prove a 503 path in `checks.spec.ts` (stubbed inputs) and the real round-trip in `test/integration/delivery.spec.ts`.
