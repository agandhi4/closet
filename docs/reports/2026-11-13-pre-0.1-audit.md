## 1. Headline: is closet ready for 0.1?

All nine household jobs can be completed on a 390 px phone and none is blocked: dressing from Today is one tap, the composer, packing ticks, offline reads and queued writes work, and pages cost 2-4 statements at 6-8 ms. It is not ready to tag today, for two verified P1s that are each a small fix: production logs synchronously to `app.log` on the hard NFS mount (a NAS stall freezes the whole app, not just photos), and the README quick start crash-loops because `PWA_ENABLED=true` ships without an https `SITE_URL`. Behind those sit 77 contained P2s that cluster into about a dozen root causes, and the ones a household will feel first are suggestion quality in winter (the same jeans and parka on every card, nonsense workout plans), phone ergonomics (fields under 16 px that make iOS zoom, 24-32 px controls), dead taps on any htmx error, and an offline cache that empties after every deploy. The operational edge is the weakest part: no restore has ever been rehearsed, the first reconciliation after a restore deletes recent photos, and the nightly workflow that runs WebKit, Lighthouse and the page audit has been an invalid file since #532. A public 0.1 also needs decisions only the owner can make: the release identity (semver tags are forbidden by a standing decision and `package.json` says 0.5.1), the AGPL source link and licence text for a public repo and image, and whether Muse must be askable from the phone.

Nothing found is a P0. No IDOR, no cross-user cache leak, no SSRF, no vulnerable production dependency (0 of 405).

**P1: obs-applog-sync-nfs.**
- Evidence: `src/logger.ts:167-176` opens `pino.destination({ dest: DATA_PATH/app.log, mkdir: true, sync: true })` beside stdout. Production `DATA_PATH` is `/mnt/closet`, a hard NFS mount; the homelab README records (2026-11-12) "when the link stalls, node blocks in NFS I/O". The access line is an `fs.writeSync` on every non-static request, so a stall blocks `/health/live`, database-only pages and timers. No `error` listener is attached anywhere in `src/`, and sonic-boom's sync path emits `error` on ENOSPC, so on a full share the logger call itself throws, including the crash handler's `logger.fatal` (read from source, not reproduced). The file is never rotated and duplicates stdout, which Docker rotates and Alloy ships to Loki.
- Recommendation: delete the destination. If a file is wanted for hand debugging, make it an opt-in `LOG_FILE` on local disk, async, with an `error` listener that drops to stdout. Remove `app.log` from the `docs/operations.md` permissions table and the `/file` route comments in the same change.

Downgraded from P1 (both split 1 for P1, 1 for P2):
- **err-db-outage-raw-json.** The root preValidation hook (`src/app.ts`) awaits `resolveSession` before setting `reply.locals`; when the lookup throws, `handleError` sends `{"statusCode":500,...}` as the document, and the worker's NetworkFirst does not fall back on a 500. Fix: session-less `ViewContext` on a resolver failure, a typed 503 `busy` for connection-class errors (captured once per outage), and a worker fallback on 503 with the freshness stamp.
- **err-htmx-dead-taps.** `HTMX_CONFIG` is `{ disableInheritance, historyCacheSize }`, so htmx's default no-swap for 4xx/5xx stands; the only `htmx:responseError` listeners probe connectivity and re-enable a button; htmx `timeout` is unset. Wears, washes, packing ticks and autosave are covered by their own paths, which is why verifiers split. Fix: top-15 #6.

## 7. Missing capabilities a household user would expect

Drawn from the journeys and gap reviews; each is absent today.

- **Ask Muse from the phone.** A round can only be started from Claude Code or Desktop on a laptop.
- **A partner who can do the laundry or see the plan.** A share covers the garment grid; MANAGE cannot mark washed in the UI though the MCP tool accepts `ownerId`. View-only shows price and private notes with no switch.
- **A real backup and a way back in.** The export is a garment spreadsheet with links; no archive of outfits, wears, selfies or photo bytes, and no import.
- **Stop sharing.** A public garment or outfit link cannot be revoked; invites do not expire; there is no "sign out everywhere".
- **Seeing and undoing what the agent did.** No attribution on agent writes, no activity list, no read-only token.
- **Search the way people describe clothes** ("blue shirt"), a sort on the grid, category quick-chips.
- **Bulk organize**: select all, bulk archive, wash, add to capsule; a selection that survives an apply.
- **Everyday garment types**: socks, underwear, swimwear, sleepwear; activewear as a purpose the planner respects.
- **Anything prefilled from a photo** (not even colour) and colour from a shop link. Reviewers class the photo guess as a later addition.
- **A first-run path**: nothing says what the app is or that the first step is a photo.
- **Trips that the home calendar knows about**, a one-tap "fill the trip", the destination resolved once, and destination-local forecast hours.
- **Queued "Worn?" on a planned entry offline** (the morning action; garment-level "Wore today" already queues).
- **An error message when a tap fails**, and Undo instead of a system confirm for reversible deletes.
- **Safe-by-default registration** on a fresh install, and an upgrade contract for anyone on the public image.
- **A named release they can pull** and notes saying what 0.1 contains.
- **Text that scales**: fields that do not zoom on iOS, layouts that hold at 200% on Android.

Deliberately absent and endorsed by reviewers: OAuth and refresh tokens, a theme toggle, per-user time zones, object storage, a second replica, native push.
